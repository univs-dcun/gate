# match 서비스의 적용된 마이그레이션 지문 (UG-312, UG-313 으로 이 서비스에 분산)
#
# Flyway 는 파일 **내용 전체**를 체크섬으로 잡는다. 이미 적용된 파일을 고치면 — 주석 한 줄,
# 공백 하나라도 — 그 환경의 다음 기동에서 validate 가 실패한다. validate-on-migrate 기본값이
# true 이고 컨테이너는 restart: unless-stopped 라 그대로 크래시 루프가 된다.
#
# 그래서 이 파일이 지문을 붙들고 있다. 같은 모듈의 MigrationChecksumGuardTest 가 대조한다.
# 이 파일에는 match 것만 담는다 — 형제 서비스는 각자의 가드와 기록이 본다 (UG-313).
#
# 값을 고쳐야 한다면:
#   - 새 마이그레이션을 추가했다 → 줄을 추가한다. 정상이다.
#   - 기존 줄의 해시가 달라졌다 → 그 파일을 고쳤다는 뜻이다. 아직 어디에도 적용되지 않았다고
#     확신할 수 있을 때만 갱신한다. dev 에 한 번이라도 배포됐다면 되돌리는 것이 답이다.
#     정말 고쳐야 하는 내용이면 새 버전으로 낸다.
#   - 줄을 지웠다 → 마이그레이션 파일 삭제도 같은 사고다. 이미 적용한 환경은 "적용됐는데
#     파일이 없다"(missing) 로 validate 가 실패한다.
#
# 갱신 명령 (backend/match 에서):
#   find src/main/resources/db/migration -name '*.sql' | sort | \
#     while read f; do echo "match/$(echo $f | sed 's|src/main/resources/db/migration/||') \
#       $(shasum -a 256 $f | cut -d' ' -f1)"; done
#
# 형식: {서비스}/{방언}/{파일명}  sha256
