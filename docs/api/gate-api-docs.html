API Reference

Gate Service API

얼굴 인식 기반 e-KYC 게이트 서비스의 공식 API 레퍼런스입니다. 얼굴 특징점 관리, 1:1 확인, 1:N 매칭, 라이브니스 감지 기능을 REST API로 제공합니다.

Base URLhttps://api.univsgate.com
Versionv1.0
ProtocolHTTPS · REST
FormatJSON / Multipart

소개

UnivsGate API는 프로젝트별 API Key를 기반으로 얼굴 인식 기반 e-KYC 기능을 외부 서비스에 통합할 수 있는 RESTful API입니다. JWT 인증과 API Key 인증을 함께 사용하며, 파일 업로드가 필요한 엔드포인트는 multipart/form-data 형식을 사용합니다.

API를 사용하기 전에 관리 페이지에서 회원가입 및 로그인 후 프로젝트를 생성하고 API Key를 발급받으세요. API Key는 모든 e-KYC 요청에 필수 인증 수단입니다.

모든 API 응답은 {"success": boolean, "data": ..., "errors": ...} 형식의 통일된 구조로 반환됩니다.

지원 생체인증 모듈

👤얼굴 인식 (Face)

얼굴 특징점 등록/관리 및 매칭(1:1 확인, 1:N 매칭, 라이브니스)을 지원합니다.

Base: /api/v1/feature/face

Base URL

Base URLhttps://api.univsgate.com/api/v1

인증 방식

특징점 관리 및 매칭 API는 두 가지 인증 헤더가 모두 필요합니다. 로그인 API는 인증이 불필요합니다.

🔐JWT Bearer Token

로그인 후 발급된 accessToken을 Authorization 헤더에 포함합니다.

Authorization: Bearer {accessToken}

🔑API Key

프로젝트별로 발급된 API Key를 X-Api-Key 헤더에 포함합니다. accessToken을 발급받은 계정이 소유한 프로젝트의 키여야 하며, 그 프로젝트가 삭제되지 않은 상태여야 합니다 — 다른 계정의 키를 사용하거나 삭제된 프로젝트의 키를 사용하면 PJ-105로 거부됩니다. 프로젝트를 삭제하면 그 프로젝트의 API Key는 즉시 비활성화됩니다.

X-Api-Key: {apiKey}

응답 구조

모든 응답은 success · data · errors 세 필드로 감싸 반환됩니다. 실패는 대부분 HTTP 400이며, 액세스 토큰이 무효로 판정된 경우에는 본문 없이 401이 반환됩니다. 상태 코드별 정리와 처리 방법은 ERRORS › 오류 응답 형식 페이지를 참고하세요.

✅ 성공 응답

{
  "success": true,
  "data": { ... },
  "errors": null
}

❌ 오류 응답

{
  "success": false,
  "data": null,
  "errors": {
    "code": "ERROR_CODE",
    "type": "ERROR_TYPE",
    "message": "..."
  }
}

타임존 처리

응답의 날짜/시간 필드는 기본적으로 UTC 기준입니다. Accept-TimeZone 헤더로 원하는 타임존을 지정하면 자동 변환됩니다.

ExampleAccept-TimeZone: Asia/Seoul

다국어 처리

한국어/영어를 지원합니다. Accept-Language 헤더로 원하는 언어를 지정하면 자동 변환됩니다.

ExampleAccept-Language: ko

Auth › 토큰 재발급

얼굴 이미지에서 특징점 디스크립터(descriptor)를 추출합니다. 추출된 디스크립터는 verify/descriptor(1:1 확인), descriptor(등록), identify/descriptor(1:N 매칭) API에서 사용할 수 있습니다.
POST/api/v1/feature/face/extract
Authorization
🔐  JWT Bearer + X-Api-Key 필요
Request Body

Content-Type: multipart/form-data

ParameterTypeRequiredDescription
featureImagefileREQUIRED특징점 추출할 얼굴 이미지 (jpg, jpeg, png)
transactionUuidstringOPTIONAL요청 식별 UUID (최대 36자)
Response Fields
FieldTypeDescription
descriptorstring추출된 얼굴 특징점 디스크립터 (Base64 인코딩된 벡터)
Response Example
200추출 성공
SuccessJSON
{
  "success": true,
  "data": {
    "descriptor": "AAABAAAAAAAAAAAA..."
  },
  "errors": null
}

  "success": false,
  "data": null,
  "errors": {
    "code": "FACE-008",
    "type": "FACE_NOT_FOUND",

  }
}

Face Match › 1:N 후보 목록 (특징점)
얼굴 1:N 후보 목록 — 디스크립터 기반
1:N 매칭 (특징점)과 같은 방식으로 비교하되, 가장 유사한 한 명이 아니라 지정한 유사도 이상인 대상자 목록을 반환합니다. 판정 기준(threshold)과 최대 인원 수(maxCandidates)를 요청에서 직접 지정한다는 점이 다릅니다. 라이브니스 검사는 수행하지 않습니다.
POST/api/v1/feature/face/identify/descriptor/candidates
Authorization
🔐  JWT Bearer + X-Api-Key 필요
Request Body

Content-Type: application/json

ParameterTypeRequiredDescription
descriptorstringREQUIRED매칭할 특징점 디스크립터. 특징점 추출 API 응답을 가공 없이 그대로 전달합니다 (base64 696자 고정 = 520바이트)
thresholddecimalREQUIRED후보로 인정할 최소 유사도 (0 초과 100 이하, 백분율). 응답의 similarity 와 같은 척도이며 소수점을 쓸 수 있습니다 (예: 85.5). 이 값 이상인 대상자만 반환됩니다
maxCandidatesintegerOPTIONAL반환받을 최대 인원 수 (1 이상 100 이하, 기본값 1). 조건을 만족하는 대상자가 이보다 적으면 그만큼만 반환됩니다
transactionUuidstringOPTIONAL요청 식별 UUID (최대 36자)
Response Fields
FieldTypeDescription
matchingHistoryIdlong매칭 이력 ID. 후보가 여러 명이어도 요청 하나당 이력은 한 건이며, 대표값으로 유사도가 가장 높은 후보가 기록됩니다
projectIdlong프로젝트 ID
matchTypestring매칭 유형 — IDENTIFY (다른 1:N API와 동일한 값입니다)
matchingTimedatetime매칭 수행 일시
successboolean후보가 1명 이상이면 true
candidatesarray조건을 만족한 대상자 목록. 유사도가 높은 순으로 정렬되며 비어 있을 수 있습니다
candidates[].featureIdstring대상자의 특징점 featureId
candidates[].userDescriptionstring특징점 등록 시 저장한 설명. 등록 시 지정하지 않았으면 null
candidates[].similaritydecimal유사도 점수 (0.00 ~ 100.00, 백분율)
thresholddecimal요청에 사용된 판정 기준 (요청값을 그대로 반환)
failureTypestring실패 코드 (NOT_MATCH 등, 성공 시 빈 문자열)
failureReasonstring실패 원인 메시지
transactionUuidstring요청 식별 UUID

제출된 얼굴 이미지가 실제 생체인지 감지합니다. 사진, 영상, 마스크 등을 이용한 스푸핑 시도를 방지합니다.
POST/api/v1/feature/face/liveness
Authorization
🔐  JWT Bearer + X-Api-Key 필요
Request Body

Content-Type: multipart/form-data

ParameterTypeRequiredDescription
matchingFeatureImagefileREQUIRED라이브니스 검사할 얼굴 이미지 (jpg, jpeg, png)
transactionUuidstringOPTIONAL요청 식별 UUID (최대 36자)
Response Fields
FieldTypeDescription
successboolean라이브니스 통과 여부
failureReasonstring실패 원인 메시지 (성공 시 null)
transactionUuidstring요청 식별 UUID
consentSnapshotboolean동의 여부 스냅샷

History › 매칭 이력 목록
매칭 이력 목록 조회
프로젝트에서 발생한 e-KYC 이력을 페이지네이션으로 조회합니다. 인증 시도(1:1·1:N·라이브니스)와 특징점 관리 사건(등록·삭제)이 한 목록에 시간순으로 섞여 내려오며, 항목의 source로 구분합니다. matchType으로 기능별, featureType으로 모듈별 필터링이 가능합니다.
GET/api/v1/match
Authorization
🔐  JWT Bearer + X-Api-Key 필요
Query Parameters
ParameterTypeRequiredDescription
matchingKeywordstringOPTIONAL매칭 검색 키워드
matchTypestringOPTIONAL이력 타입 필터. 인증: VERIFY | VERIFY_ID | VERIFY_IMAGE | VERIFY_DESCRIPTOR | IDENTIFY | LIVENESS / 특징점 관리: REGISTER | DELETE / ALL (기본값: ALL — DELETE 는 includeDeletions=true 일 때만 포함)
includeDeletionsbooleanOPTIONALmatchType=ALL 일 때 삭제(DELETE) 이력을 포함할지 (기본값: false — 기존 클라이언트 호환). matchType=DELETE 를 명시하면 이 값과 무관하게 조회됨
featureTypestringOPTIONAL특징점 타입 필터 (FACE | ALL, 기본값: ALL)
matchResultTypestringOPTIONAL매칭 결과 필터 (SUCCESS | FAILURE | ALL, 기본값: SUCCESS)
pageintegerOPTIONAL페이지 번호 (기본값: 1, 범위: 1~1000)
pageSizeintegerOPTIONAL페이지 크기 (기본값: 10, 범위: 1~1000)
startDatestringOPTIONAL조회 시작일 (yyyy-MM-dd, startDate·endDate를 함께 보내야 적용됨)
endDatestringOPTIONAL조회 종료일 (yyyy-MM-dd, startDate·endDate를 함께 보내야 적용됨)

History › 이력 단건 조회
트랜잭션 UUID 기반 이력 조회
요청 시 전달한 transactionUuid로 해당 매칭 이력을 단건 조회합니다. 매칭 API 응답을 수신하지 못한 경우 결과를 다시 확인하는 용도로 사용합니다.
GET/api/v1/match/{transactionUuid}
Authorization
🔐  JWT Bearer + X-Api-Key 필요
Path Parameters
ParameterTypeRequiredDescription
transactionUuidstringREQUIRED매칭 요청 시 전달한 요청 식별 UUID
Response Fields
FieldTypeDescription
matchingHistoryIdlong이력 식별 번호. source 와 함께 유일하다 — MATCH 와 FEATURE 는 번호 공간이 다르므로 목록에서 같은 숫자가 두 번 나올 수 있다
projectIdlong프로젝트 식별 번호
featureTypestring특징점 타입 (FACE)
matchTypestring이력 타입. 인증: VERIFY | VERIFY_ID | VERIFY_IMAGE | VERIFY_DESCRIPTOR | IDENTIFY | LIVENESS / 특징점 관리: REGISTER | DELETE
sourcestring이력 출처 (MATCH: 인증 시도 | FEATURE: 특징점 등록·삭제). FEATURE 행에는 similarity·matchingFeatureImagePath 가 null
matchingTimedatetime매칭 시간
checkLivenessboolean라이브니스 검사 수행 여부
successboolean매칭 성공 여부
featureIdstringAI 서버 특징점 식별 ID
featureSeqlong특징점 식별 번호 (faceFeatureId)
descriptionstring특징점 설명
similaritynumber매칭 유사도 (source=FEATURE 이면 null)
featureImagePathstring등록된 특징점 이미지 경로
matchingFeatureImagePathstring매칭 시도 이미지 경로 (source=FEATURE 이면 null)
failureTypestring매칭 실패 타입 (성공 시 null)
failureReasonstring매칭 실패 사유 (Accept-Language에 따라 다국어 처리, 성공 시 빈 문자열)
transactionUuidstring요청 식별 UUID
consentSnapshotboolean사건 시점의 개인정보 수집 동의 설정값 (matchType=DELETE 이면 null)
createdAtdatetime이력 생성 일시
